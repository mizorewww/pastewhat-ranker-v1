# Train finite-vocabulary source amendment

Snapshot: 2026-09-23 13:40 UTC. This report uses only Train production aggregates and registered source metadata; it contains no episode text or held-out labels.

The original 2,000 batches and all seven registered replacement rounds are complete. The rolling pool has 19,986 of 20,000 required unique original quota slots, so the original finite seven-round source budget ended with status `finite_backfill_exhausted`. Replacement-round accepted counts were 523/934, 361/411, 28/50, 7/22, 0/15, 1/15, and 0/14. All original and round 1–7 source registrations, seeds, labels, audits, and accepted rows remain untouched.

Eleven of the fourteen residual slots are `http_method` with no accessibility context or a generic method field: nine require four clipboard candidates and two require three. The source family permits only bare `GET`, `POST`, `PUT`, and `DELETE`. The content fingerprint deliberately ignores candidate order, because order alone does not produce a new decision. Four distinct methods at candidate count four therefore produce exactly one visible candidate set, already accepted for each observation variant. Later attempts repeatedly generated that set and were correctly rejected by global content deduplication. This is a finite source-space issue, not evidence for changing an independent label or weakening deduplication. The other three residual slots belong to separate families and remain under their unchanged authoring rules.

An explicitly versioned Train-only amendment permits replacement rounds 8–12 for only original quota slots still unfilled at each round. The first new round receives a new `-replacement-08` batch/episode suffix, deterministic replacement seed, immutable registration file, and registration SHA. Subsequent rounds use their own numbered suffix and seed. The existing run plan and all quota factors remain fixed. A supervisor treats the prior seven-round exhaustion record as superseded only because the new finite bound is 12; it does not modify that audit record.

For a newly registered unobserved `http_method` missing-intent plan, `train-http-method-unobserved-multiset-v1` deterministically assigns an unused **multiset of actual clipboard texts** from the four permitted methods. Every entry is a bare valid method, candidate count is unchanged, and at least two distinct methods remain plausible mutually exclusive choices. Repeated entries model a real clipboard history containing the same method more than once. The assignment uses accepted Train visible candidate sets and reserves combinations within the new registration, favoring three distinct methods where possible. The author receives exact candidate texts as source-only plan constraints; the pre-label gate verifies the authored and prepared student-visible texts exactly, plus empty guidance and selection. It rejects invalid methods, changed candidate counts, or altered source constraints before independent labeling. The independent labeler can still reject any candidate set. Frozen Train publication replays this versioned gate against the saved author audit and checks content identity and source provenance.

Offline against the seven-round rolling pool, round 8 would register 14 batches for exactly 14 unfilled original slots, with zero overlap. Eleven versioned HTTP slots receive eleven distinct visible candidate multisets, each unused in the shared content registry. All 14 plans preserve their original family, scenario, candidate count, language, and observation variant. Positive and negative local gate checks passed without a teacher request. This is a source-diversity repair within a narrow synthetic distribution; it does not establish deployment accuracy.
